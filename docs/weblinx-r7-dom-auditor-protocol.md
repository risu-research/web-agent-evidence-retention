# R7: Actual Playwright DOM snapshot auditor vs selective packet auditor

Declared November 22, 2026 before inspecting any new R7 trace snapshots. R6 and R5B original source results are frozen. R7 re-executes **the same fixed 48 Django Admin actions** and their untouched upstream Django 5.2.12 SQLite backend, using the same 2 × 3 × 8 experiment, version, Chromium, negative controls and separate independent DB readback. No original R6 source cases are relabeled.

## Two isolated auditors, identical questions

**Auditor T (Trace-only)** receives an original unmodified Playwright Trace ZIP from a fresh R7 episode, a static mapping for dummy record labels A/B and the announced intent (A). It may inspect the ZIP's actual `.trace` action events, `frame-snapshot` DOM trees, `.network` network records and other native trace records, and recursively decode compact Playwright DOM snapshots. It may use before/action/after snapshots and navigation state to infer:
- Q1: submitted first-click selector (literal trace expression);
- Q2a: visible application row of the first actual action, *inferred* from action/DOM/links; **not** a direct independent `isTrusted` event;
- Q3: user mutation route receiving HTTP POST, or evidence of absence;
- Q4a: final persisted effect **inferred from post-action DOM** (user list and first-name values); distinguish this UI inference from Q4b authoritative committed SQL, which requires a separate DB oracle;
- Q5: first action completed or errored.

**Auditor P (packet-only)** receives only the actual serialized request/event/server/effect packet generated by the original browser+observer+WSGI+SQLite measurement, not Trace, trace-derived fields or evaluation truth. It is evaluated at three successive retention tiers: request+event, request+event+server, and request+event+server+effect. The full packet includes the independent SQL readback by construction. Preserve all byte sizes.

A blind **evaluation join** compares both auditors' frozen per-case answers with the original independent event observer, WSGI and new SQLite connection **after** each auditor has produced its answers. Neither auditor reads the other’s output or the truth CSV during inference.

## Comparable audit questions and scores

For each of 48 source case keys, score every question separately as **correct**, **wrong**, or **abstain**; report coverage and accuracy among answered with exact denominators. Q1: attempted first-click selector expression or declared locator type; note the two fields differ in specificity. Q2: actual visible row of the trusted click A/B/none. T estimates using DOM/actions (count as *inferred*, never as observed), P from independent `isTrusted` capture. Q3: WSGI received a mutation POST A/B/none; native trace network vs packet server records. Q4: actual database effect A/B/none; T may predict using final DOM but can never claim independently authenticated SQL, P reads the real SQL oracle (explicitly privileged). Q5: first click status returned vs error from action records/API. Record error types and ambiguous/multiple events. A correct no-event or no-effect prediction is still an evaluated answer; do not blindly equate “unknown” and “none.”

For fairness: classify T's Q4 answer as **browser-visible inference**, P's as **independent effect evidence**, and report them both on empirical correctness and evidence strength. Do not call different instrumentation equally privileged or comparable in security guarantee. Separately measure both products' actual stored sizes: full native Trace ZIP vs per-case compressed evidence packets, without claiming functional equivalence.

## DOM snapshot parser and validation

Before full evaluation, run a separate one-case **format-discovery smoke test** on the same dummy Django app. The smoke test may print only JSON event types, snapshot field names, compact DOM tree node shapes, and counts; never display/upload raw page HTML, cookies, URLs with real data, or trace resource bytes. No empirical label is accepted from this step. Use the resulting verified format to implement a generic recursive DOM snapshot decoder with explicit handling of Playwright subtree-reference encodings (or conservatively abstain if references cannot be resolved). Prove decoder correctness on hand-constructed cases and compare a few source snapshot properties with controlled dummy DOM. Avoid substrings of raw trace JSON as if they were reconstructed DOM.

The auditor must be executed *inside the per-case runner while the raw Trace exists*, and return numeric/categorical results; the raw Trace ZIP must be deleted after processing. Do not send any raw Trace ZIP to an LLM, a third-party API, the GitHub artifact or the public repository.

## Source, failure policy and stopping rules

Django Admin/ORM/model/routes remain untouched. R7 code may wrap the prior R6 episode orchestration and introduce trace and packet auditors; any modifications to R6's original 48-case source experiment must be disclosed and strictly limited to harness instrumentation.

First preregister this protocol; then run a one-case trace format smoke test before any full R7 results. Freeze parser/matcher rules before opening R7 evaluation outcomes. Negative controls baseline all 6 effects A, standard overlay all 6 no effects, authenticated observer and SQL readback intact. All 48 cases included, even when parser abstains or gets answers wrong. Independent second full source run must reproduce categorical conclusions, with actual Trace timing/byte variability reported separately. Do not change main manuscript/Zenodo DOI until this stricter comparison passes.

Potential limitation: T may infer final UI changes very successfully from complete browser Trace snapshots. If so, report that as a positive result for Playwright, not as failure of the proposed method. No production failure-rate inference, no LLM-as-judge.
